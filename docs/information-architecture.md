# 정보 구조 (IA)

## 결론

**홈 · 발견 · 경기 · 마이야구 · 더보기** 5탭.

이 문서는 왜 이 구조인지, 어떤 대안을 검토하고 왜 기각했는지, 그리고 그 판단을
무엇으로 확인했는지를 적습니다.

**검증 방식에 대한 정직한 고지**: 채택안은 코드로 구현해 위젯 테스트에서 탭 수와
스크롤 수를 **실측**했습니다. 대안 A·B는 구현하지 않았고, 같은 과업 목록에 대해
화면 인벤토리를 기준으로 **경로를 세어 비교**했습니다. 실사용자 테스트는 하지
않았습니다 (`docs/user-testing-plan.md` 참고).

---

## 문제 정의

한 앱이 성격이 다른 두 사람을 동시에 상대해야 합니다.

| | 입문자 (방송 유입) | 현역 (선수·운영진) |
| --- | --- | --- |
| 첫 질문 | "이거 뭐 보는 거지? 재밌나?" | "우리 다음 경기 언제, 비 오나?" |
| 팀 애착 | 없음 | 강함 |
| 방문 빈도 | 낮고 불규칙 | 높고 규칙적 |
| 실패 신호 | 점수표만 보이면 이탈 | 세 번 눌러야 일정이 나오면 이탈 |
| 스포일러 | 민감 (방송 시청 전) | 대체로 무관 |

**한 앱을 두 앱으로 쪼개지 않고**, 한 화면을 무한정 길게 만들지도 않으면서
둘 다 만족시키는 것이 목표입니다.

---

## 검토한 3안

### 대안 A — 4탭: 홈 · 경기 · 팀 · 더보기 (전형적 스포츠 앱)

가장 흔한 구조. 기각 이유:

- **입문자에게 줄 자리가 없습니다.** 화제 콘텐츠·가이드·근처 경기가 갈 곳은
  홈뿐이고, 홈은 이미 일정과 결과로 차 있습니다. 결국 홈이 끝없이 길어집니다.
- **"팀" 탭이 애매합니다.** 입문자는 팀 목록을 볼 이유가 없고, 현역은 자기 팀
  하나만 봅니다. 두 사람 모두에게 목적지가 아닙니다.
- 근처 경기까지: 홈 → 스크롤 → 진입 = **2탭 + 스크롤**.

### 대안 B — 3탭: 홈 · 경기 · 나 (모드가 전부를 바꾸는 구조)

모드에 따라 앱 전체가 달라지는 구조. 기각 이유:

- **모드를 잘못 고른 사용자가 갇힙니다.** 온보딩은 건너뛸 수 있어야 하는데,
  건너뛴 사람에게 보여줄 기본형이 마땅치 않습니다.
- **두 앱을 한 바이너리에 넣은 것**과 같아서, 화면마다 두 벌의 상태를 관리하게
  됩니다. 유지비가 기능 대비 큽니다.
- 발견 계층이 홈에 흡수되면 스포일러 정책을 적용할 표면이 넓어집니다.

### 채택 — 5탭: 홈 · 발견 · 경기 · 마이야구 · 더보기

- **발견**과 **마이야구**가 각 사용자의 **고정 목적지**입니다. 모드를 잘못 골라도
  탭이 사라지지 않으므로 갇히지 않습니다.
- **모드는 홈의 모듈 순서만 바꿉니다.** 접근 가능한 기능은 모든 모드에서 같습니다.
  이건 표시 설정이지 기능 차단이 아닙니다.
- 팀·선수·대회는 탭에서 빠졌지만 사라지지 않았습니다. **검색**(모든 탭에서 1탭)과
  맥락 진입(경기 상세 → 팀, 마이야구 → 팀 찾기)으로 닿습니다.

### 탭 수 비교 (같은 과업, 같은 화면 인벤토리)

| 과업 | 대안 A | 대안 B | **채택** |
| --- | ---: | ---: | ---: |
| 내 팀 다음 경기 상세 (현역) | 2 | 1 | **1** |
| 근처 경기 찾기 | 2 + 스크롤 | 2 | **2** |
| 마이야구 진입 | 3 | 1 | **1** |
| 통합 검색 | 1 | 1 | **1** |
| 입문 콘텐츠 도달 | 1 + 긴 스크롤 | 1 | **1** |
| 내 팀 설정 | 2 | 2 | **2** |

채택안의 숫자는 실측값입니다 (`test/widget/task_benchmark_test.dart`).
A·B는 경로를 세어 추정한 값입니다.

대안 B도 탭 수만 보면 대등하지만, 위에 적은 "갇힘"과 유지비 문제 때문에
기각했습니다. **탭 수는 여러 기준 중 하나이지 유일한 기준이 아닙니다.**

## 탭별 역할

| 탭 | 역할 | 주 사용자 |
| --- | --- | --- |
| 홈 | 오늘. 모드에 따라 모듈 순서가 달라짐 | 둘 다 |
| 발견 | 화제·방송·뉴스 묶음·가이드·근처 경기 | 입문자 |
| 경기 | 일정·결과·대회·순위 | 둘 다 |
| 마이야구 | 30일 일정판·날씨·참석·순위·기록 | 현역 |
| 더보기 | 출처·설정·제보·법적 고지 | 둘 다 |

**검색은 탭이 아닙니다.** 모든 주요 화면의 앱바에 있어서 어디서든 1탭입니다.
탭 하나를 검색에 쓰면 나머지 넷의 자리가 부족해집니다.

## 홈: 모듈 순서가 곧 모드

홈은 고정 레이아웃이 아니라 **모듈 목록**입니다. 순서는 데이터이고
`AudienceMode` 로 결정되며, 사용자가 접거나 재정렬할 수 있습니다.

### 입문자 (`discover`)

```
지금 화제 → 방송 다시 보기 → 이번 주말 가까운 경기 → 주요 소식
→ 내 관심 소식 → 여자야구 1분 이해 → 공식 영상 → 다가오는 경기
→ 최근 결과 → 여자야구 시작하기
```

점수를 **없애지 않았습니다.** 팀 애착이 없는 사람에게 관심을 가질 이유를 먼저 준
뒤로 내렸을 뿐입니다.

### 현역 (`player`)

```
내 팀 다음 경기 → 경기일 날씨 → 앞으로 30일 → 내 팀 순위
→ 리그 현황 → 기록 부문 선두 → 내 팀 소식 → 공지 → 지금 화제
```

첫 화면 최상단이 "내 팀 다음 경기"입니다. **1탭에 상세로 갑니다** — 실측 확인.

### 둘 다 (`both`)

두 목록을 이어 붙이지 **않았습니다.** 이어 붙이면 화면이 두 배가 되고 아무도
끝까지 안 봅니다. 급한 현역 항목 → 가장 강한 발견 항목 → 나머지 순으로 섞고,
**길이는 한 목록 수준**으로 유지합니다.

```
내 팀 다음 경기 → 경기일 날씨 → 지금 화제 → 이번 주말 가까운 경기
→ 내 팀 순위 → 주요 소식 → 리그 현황 → 방송 다시 보기 → 다가오는 경기
```

### 접기 규칙

각 모드의 **선두 모듈은 접을 수 없습니다** (`isCollapsible == false`).
화면이 자기 존재 이유인 질문에는 항상 답해야 합니다. 나머지는 전부 접힙니다.

### 재정렬 안전장치

저장된 순서는 현재 모드의 모듈 집합으로 **필터링**됩니다. 그래서 모드를 바꿔도
고아 모듈이 남지 않고, 새로 추가된 모듈이 조용히 빠지지도 않습니다.

## 온보딩

3단계, **전부 건너뛸 수 있습니다.**

1. 모드 (알아가는 중 / 하고 있어요 / 둘 다)
2. 지역과 관심 팀
3. 스포일러 정책

**알림 권한을 여기서 요청하지 않습니다.** 첫 화면에서 권한을 묻는 것은 앱이
자기 이야기부터 하는 것입니다. 사용자가 알림을 실제로 켜는 시점에 묻습니다.

**위치 권한도 요청하지 않습니다.** 지역(시·도) 선택만으로 근처 경기가 동작합니다.

건너뛴 사용자는 `discover` 모드로 시작하고, 홈 최상단에 "지금 화면: ○○ / 바꾸기"
배너가 뜹니다.

## 스포일러

방송 유입 사용자에게는 결과 노출이 실질적인 피해입니다.
정책은 **카드·상세·알림 전부**에 적용됩니다. 한 곳만 가리면 다른 곳에서 새고,
그러면 설정이 있으나 마나입니다.
