# 경쟁 앱 분석 (Competitor Audit)

조사일: 2026-08-30
조사 방법: 각 서비스의 **공식 도움말 / 공식 기능 페이지 / 스토어 설명**을 직접 확인.
스크린샷·문구·브랜드 자산은 복제하지 않았고, **작동 원리만 추출**했다.

> 확인 한계: OneFootball 헬프센터와 AllTrails Plus 페이지는 자동 조회 시 HTTP 403을 반환해
> 직접 본문을 읽지 못했다. 해당 두 건은 **검색 결과에 노출된 공식 헬프센터 문서 요약**과
> 공개 스토어 설명에 근거했으며, 아래 표에 `간접 확인`으로 표시했다.
> 사용자 리뷰 통계(별점 분포 등)는 신뢰할 수 있는 원문을 확보하지 못해 수치로 인용하지 않았다.

## 2. 앱별 상세

### 2.1 OneFootball  *(간접 확인)*

출처: [OneFootball Help Center – What does the app offer](https://onefootballsupport.zendesk.com/hc/en-us/articles/4412970161937-What-does-the-OneFootball-app-offer),
[Following competitions, players, clubs](https://onefootballsupport.zendesk.com/hc/en-us/articles/4404631729809-How-to-Follow-Competitions-Players-and-Clubs-on-OneFootball),
[Personalize your teams notifications](https://onefootballsupport.zendesk.com/hc/en-us/articles/4404491690513-Personalize-your-teams-notifications)

1. **첫 가치 시점**: 팀을 하나라도 팔로우하면 바로 개인화된 뉴스가 뜬다.
2. **홈 우선순위**: `For You`는 팔로우한 팀·선수·대회 기반 뉴스 큐레이션. 스코어보다 **뉴스가 상단**.
3. **관심 설정**: 팀/선수/대회 페이지의 ⭐ 또는 Follow 버튼. 상단 우측에 대표 팀 로고, 옆 화살표로 팔로우 목록 열람.
4. **재방문 장치**: 팔로우 팀 뉴스 갱신, 다음 경기 표시.
5. **알림 제어**: Profile → Push Notifications에서 **팔로우한 팀·선수별로 개별 조정**.
6. **긴 표 처리**: 하단 4개 탭으로 영역 분리.
7. **주변 찾기**: 없음.
8. **잘된 패턴 2 / 이탈 유발 1**
   - 좋음 ①: 뉴스가 스코어보다 위 — 비인기 종목/저관여 사용자에게 유효.
   - 좋음 ②: 팔로우 목록을 홈 상단에서 바로 전환.
   - 나쁨: 대형 리그 기준의 정보량. 데이터가 얕은 종목에서 그대로 하면 빈 카드가 된다.
9. **적용**: `발견` 탭의 `이야기 묶음` 리스트, 홈 상단 팔로우 전환 진입점.
10. **그대로 적용 불가**: 400개 대회급 정보 밀도. 여자야구는 표시할 경기 자체가 적어 같은 레이아웃이면 허전해 보인다.

### 2.2 FotMob

출처: [App Store – FotMob](https://apps.apple.com/us/app/fotmob-soccer-live-scores/id488575683)

1. 첫 가치: 즉시(라이브 스코어).
2. 홈: 라이브 스코어 우선, 팔로우 팀의 다음 경기와 홈/원정 표시.
3. 관심 설정: 팀·선수 팔로우.
4. 재방문: **홈 화면 위젯**, 잠금화면 Live Activity.
5. 알림: 팀·선수별 커스텀 알림.
6. 긴 표: xG, 슛맵, 히트맵 등 시각화로 표를 대체.
7. 주변: 없음.
8. 잘된 것 ①: 위젯으로 앱을 열지 않아도 가치 전달. ②: 표 대신 그래픽.
   나쁨: **리뷰에서 알림 정확도 오류(득점자 오기)** 지적 — 신뢰를 깎는 대표 사례.
9. 적용: `NextGameSummary` read model을 UI와 분리해 위젯 확장 준비(이미 구현됨).
10. 불가: xG류 고급 지표. 여자야구 공개 데이터에 존재하지 않으므로 만들어내면 안 된다.

### 2.3 Apple Sports

출처: [Apple Support – Manage My Sports](https://support.apple.com/guide/apple-sports-app/manage-my-sports-apd53158ab1f/web)

1. 첫 가치: 즉시.
2. 홈: My Sports에 담긴 팀 중심.
3. 관심 설정: 메뉴 → Edit → 검색 → 리그/팀 선택, `−` 아이콘으로 제거. **매우 짧은 편집 흐름**.
4. 재방문: 잠금화면 Live Activities.
5. 알림: **팔로우 팀별 Live Activity on/off**, 개별 경기 알림은 스와이프로 즉시 해제.
6. 긴 표: 최소화.
7. 주변: 없음.
8. 좋음 ①: 팀별 알림 토글 위치가 팔로우 목록과 같은 화면. ②: 알림에서 바로 음소거.
   나쁨: 계정(Apple Account) 동기화 전제 — 로그인 없는 앱에는 부적합.
9. 적용: `더보기 → 알림`에서 **팔로우 목록과 알림 토글을 같은 행에** 배치. 알림 본문에 "이 알림을 받는 이유"와 팔로우 해제 진입점.
10. 불가: 계정 기반 동기화. 우리는 전부 로컬.

### 2.4 Google News  ★ 가장 큰 영향

출처: [Google News Help – How stories are selected](https://support.google.com/googlenews/answer/9005749)

1. 첫 가치: 즉시.
2. 홈: **`Top stories`(같은 언어·지역이면 모두 동일) + `For you`(개인화)** 병행.
3. 관심 설정: `Following`에서 주제·출처·지역 팔로우/해제.
4. 재방문: 사건 단위 갱신, `Full Coverage`로 복수 출처 열람.
5. 알림: 주제별.
6. 긴 표: 해당 없음.
7. 주변: 지역 팔로우.
8. 좋음 ①: **개인화와 비개인화를 한 화면에 공존**시켜 필터 버블 완화. ②: 같은 사건을 하나로 묶고 **여러 출처를 병렬 제시**.
   나쁨: 알고리즘 선정 근거가 불투명.
9. 적용: `StoryCluster` 모델 + `발견` 홈의 **`모두가 알아둘 주요 소식`(비개인화) / `내 관심`(개인화)** 이중 섹션. 요약 아래 출처 목록.
10. 불가: 제목만으로 요약 생성. 우리는 **API가 제공한 합법적 description 또는 사람 검수 요약만** 사용한다.

### 2.5 GameChanger

출처: [GameChanger – App features](https://gc.com/app-features)

1. 첫 가치: 팀 등록 후.
2. 홈: 일정이 기반, 그 위에 기록이 쌓이는 구조.
3. 관심 설정: 팀 소속.
4. 재방문: 경기 후 기록·클립, 시즌 진척.
5. 알림: 팀 단위.
6. 긴 표: 경기별 → 시즌 누적으로 계층화.
7. 주변: 없음.
8. 좋음 ①: **일정 → 기록 → 시즌 리뷰가 하나의 흐름**. ②: 학부모/코치/선수별로 같은 데이터를 다른 관점으로.
   나쁨: 실시간 기록 입력·스트리밍은 서버와 운영 인력을 전제로 한다.
9. 적용: `마이야구`의 일정 → 팀 순위 → 개인 기록 연결 동선.
10. 불가: 로그인·채팅·실시간 기록 입력. 1차 범위에서 제외하고 flag만 둔다.

### 2.6 TeamSnap

출처: [TeamSnap – Features](https://www.teamsnap.com/teams/features)

1. 첫 가치: 팀 가입 후.
2. 홈: "어디로, 누가, 언제" — 일정 + 참석 가능 여부.
3. 관심 설정: 팀 소속.
4. 재방문: RSVP 요청, 일정 변경 통지.
5. 알림: 팀 커뮤니케이션.
6~7. 해당 없음.
8. 좋음 ①: **일정과 위치를 한 카드에서 해결**. ②: 참석 여부가 일정의 일부.
   나쁨: 비공개 팀 정보를 전제로 함.
9. 적용: `마이야구` 일정 카드에 구장·길찾기 결합. 향후 팀 운영 기능용 interface + 비활성 flag.
10. 불가: **비공개 팀 정보를 공개 데이터와 혼합**. 우리는 공개 일정만 다룬다.

### 2.7 Eventbrite

출처: [Eventbrite Help – Discover events](https://www.eventbrite.com/help/en-us/articles/783059/)

1. 첫 가치: 즉시.
2. 홈: `Discover` — 내 지역 이벤트 탐색, 또는 **검색으로 다른 지역 지정**.
3. 관심 설정: 지역·카테고리.
4. 재방문: 하트로 저장.
5. 알림: 문서에 명시 없음.
6. 긴 표: 해당 없음.
7. **주변 찾기**: 날짜 / 카테고리 / 가격 / 온·오프라인 필터.
8. 좋음 ①: **지역을 검색으로 직접 바꿀 수 있음** → 위치 권한 없이도 성립. ②: 저장이 1탭.
   나쁨: 문서상 위치 권한 거부 시 대체 동선이 명확히 설명되지 않음.
9. 적용: `근처 경기`에서 **위치 권한 요청 전에 시·도 선택을 먼저** 제공.
10. 불가: 가격 필터. 여자야구 대회는 관람료 정보가 대체로 미확인이므로 `확인 필요`로 표기한다.

### 2.8 MLB Ballpark

출처: [MLB Ballpark app](https://www.mlb.com/apps/ballpark)

1. 첫 가치: 티켓 보유 시.
2. 홈: 관람 당일 정보.
3~4. 팀·티켓, 방문 이력.
5. 알림: **게이트 오픈, 날씨 경보**.
6. 긴 표: 없음.
7. 주변: 구장 지도, 주차 정보, 가방 반입 정책, 게이트 개장 시각.
8. 좋음 ①: **"가기 전에 알아야 할 것"을 한 화면에 묶음**. ②: 날씨를 관람 준비의 일부로 취급.
   나쁨: 티켓·결제가 핵심 — 우리에겐 없다.
9. 적용: 경기 상세의 **`관람 준비`** 블록(구장·길찾기·날씨 위험·관람 가능 여부·공식 원문).
10. 불가: **결제·예매 흐름을 흉내내지 않는다.** 관람료가 미확인이면 `무료`로 추정하지 않고 `확인 필요`로 표시.

### 2.9 AllTrails  *(간접 확인)*

출처: [AllTrails Plus](https://www.alltrails.com/plus/info) (403 — 공개 스토어/마케팅 설명 기반)

1. 첫 가치: 즉시(주변 목록).
2. 홈: 주변 탐색 + 필터.
3. 관심 설정: 지역, 난이도·거리 필터.
4. 재방문: 저장 목록, 오프라인 지도.
5~6. 해당 없음.
7. **주변 찾기**: 거리 반경, 조건(날씨·상태) 사전 확인.
8. 좋음 ①: **가기 전 조건 확인**을 발견 단계에 통합. ②: 오프라인 저장.
   나쁨: 위치 권한 의존도가 높다.
9. 적용: `근처 경기` 필터(오늘/이번 주말/30일, 거리 반경) + 오프라인 열람.
10. 불가: 첫 실행부터 위치 권한 요구.

### 2.10 Strava

출처: [Strava – Clubs, challenges and community](https://support.strava.com/en-us/collections/19657598-clubs-challenges-and-community)

1~4. 활동 기록 후 가치, 피드 중심, 클럽·챌린지, 리더보드·kudos로 재방문.
8. 좋음 ①: **리더보드로 "내 위치"를 즉시 제시**. ②: 클럽 이벤트가 반복 접점을 만듦.
   나쁨: 경쟁 심화, 공개 부적절한 개인 정보 노출 위험.
9. 적용: `마이야구`의 **부문별 기록 리더보드**(자격 충족자/전체 구분).
10. 불가: **근거 없는 종합 점수·AI 선수 등급 금지.** 공식 공개 기록만, 정의와 자격 기준을 함께 표기.

### 2.11 KBO 공식 앱 (현 `ruta`) — 반면교사

출처: [Google Play – KBO](https://play.google.com/store/apps/details?id=com.sports2i.kbo),
[App Store – ruta](https://apps.apple.com/kr/app/ruta-kbo-%EB%A6%AC%EA%B7%B8%EB%A5%BC-%EC%A6%90%EA%B8%B0%EB%8A%94-%EA%B0%80%EC%9E%A5-%EC%89%BD%EA%B3%A0-%EB%B9%A0%EB%A5%B8-%EB%B0%A9%EB%B2%95/id610317366)

검색 요약에서 반복적으로 확인된 불만 지점(수치 인용은 하지 않음):

- 진입 시 **동영상 광고**로 흐름이 끊긴다.
- **알림 설정이 일괄적으로만 가능**하다.
- 경기 현황 알림이 늦다.
- 초기 로딩 속도가 개선 과제로 릴리스 노트에 반복 등장.

**적용(반대로 하기)**
- 첫 화면에 전면 광고·캐러셀 없음.
- 알림은 **카테고리별 on/off**(일정 변경 / 날씨 / 순위 / 회차 요약 …).
- 로딩은 **캐시 우선** — 네트워크 이전에 로컬 DB로 첫 프레임을 그린다.
- 빈 흰 화면 금지, skeleton 사용.

## 5. 대표 과업 탭 수 비교 (구 IA vs 신 IA)

`docs/task-benchmarks.md`에 측정 결과와 근거를 기록한다. 요약:

| 과업 | 구 IA (`홈/경기/대회/팀·선수/더보기`) | 신 IA (`홈/발견/경기/마이야구/더보기`) |
|---|---|---|
| 화제 콘텐츠 요약 읽기 | 3탭 (더보기 → 뉴스 → 기사) | **1탭** (홈 카드) |
| 이번 주말 근처 경기 | 3탭+ (경기 → 필터 → 지역) | **2탭** (발견 → 근처 경기) |
| 내 팀 다음 일정 + 날씨 | 2탭 + 날씨 없음 | **1탭** (마이야구) |
| 내 팀 순위 | 3탭 (대회 → 선택 → 순위) | **2탭** (마이야구 → 순위 카드) |
| 오늘 경기 결과 | 2탭 | 2탭 (동일) |

`대회`를 독립 탭에서 내리는 대신 `경기` 탭의 세그먼트와 `마이야구`의 리그 펄스로 흡수했다.
`팀·선수`는 통합 검색(모든 주요 화면에서 1탭)과 `발견 → 팀 찾기`로 접근한다.
