## 0. 이 작업에서 지켜야 할 제약

기존 제약을 그대로 승계한다. 하나라도 어기면 그 변경은 되돌린다.

- 출처가 확인되지 않은 경기 결과·선수 정보·뉴스를 만들어내지 않는다.
- 데모 데이터는 `isDemo=true` 와 화면 라벨을 유지한다. **화면·음성 양쪽에서.**
- 생성기가 자기 출력을 `reviewed` / `humanVerified` 로 표시하지 않는다.
- 기상청 예보 가능 범위(D+0~2 상세, D+3~10 범위, D+11 이후 없음)를 넘지 않는다.
- 가짜 URL을 만들지 않는다. 주소가 없으면 "준비 중"으로 둔다.
- 위치·알림 권한을 화면 진입만으로 요청하지 않는다. 위치 권한은 여전히
  요청하지 않는다.
- 정보 밀도 설정이 어떤 정보도 숨기지 않는다.
- 스포일러 기본값은 fail-closed 를 유지한다.
- 개인정보를 새로 수집하지 않는다.

### 범위 제한

- 정보 구조(5탭)와 홈 모듈 순서 체계는 **바꾸지 않는다.** 이미 근거를 갖고
  결정됐고, 이번 작업의 대상이 아니다.
- 스키마 마이그레이션(v3)이 필요한 변경은 **하지 않는다.** 별도 작업이다.
- API 키가 있어야 하는 콘텐츠 수집은 **하지 않는다.**

## 1. BUGFIX

### B1. 홈에서 내용 없는 섹션 헤더가 그대로 남는다

**증거**: `docs/audit-evidence/device/16-offline-first-run.png` —
`방송 다시 보기` 헤더 아래가 비어 있고 바로 다음 섹션이 이어진다.
`03-deeplink-after-onboarding.png` 에서도 같다.

**원인**: `_HomeModuleView.build` 가 헤더와 본문을 항상 함께 세운다.

```dart
return Column(children: <Widget>[
  _ModuleHeader(module: module, collapsed: collapsed),
  body,   // 본문이 SizedBox.shrink() 여도 헤더는 남는다
]);
```

본문이 `SizedBox.shrink()` 를 돌려줄 수 있는 모듈이 **11개**다
(`_FeaturedModule`, `_ProgramRecapModule`, `_WeekendNearbyModule`,
`_StoriesModule`, `_BeginnerGuideModule`, `_VideosModule`,
`_WeatherOutlookModule`, `_LeaguePulseModule`, `_LeaderboardModule`,
`_NoticesModule`, `_GameListModule`). 일회성 실수가 아니라 구조적 문제다.

**사용자에게 미치는 영향**: 처음 앱을 연 사람이 제목만 있고 내용이 없는 칸을
본다. 고장으로 읽히거나, 자기가 뭘 잘못한 줄 안다.

**수정 방향**: 모듈이 "내용 없음"을 **구조적으로 표현**하게 한다. 각 모듈이
본문 위젯 대신 "내용 있음 / 내용 없음" 을 알 수 있는 형태를 반환하고,
`_HomeModuleView` 가 내용이 없으면 **헤더까지 렌더링하지 않는다.**
호출 지점 11곳에 `if` 를 흩뿌리지 말 것 — 새 모듈이 같은 실수를 반복한다.

**검증**: 모든 모드 × (데이터 있음/없음) 조합에서 "본문 없는 헤더가 0개" 임을
단정하는 위젯 테스트.

### B2. 알림 권한을 거부했는데 안내가 다른 원인을 지목한다

**증거**: `docs/audit-evidence/device/06-notif-denied.png` —
시스템 권한 대화상자에서 **거부**를 눌렀는데 스낵바는
"알림 종류가 모두 꺼져 있어 알림은 가지 않습니다" 라고 말한다.

**원인**: `game_detail_screen.dart` 의 `_ReminderButton._toggle` 이 카테고리
상태만 보고 문구를 고른다. 권한 거부 여부를 확인하지 않는다.

**사용자에게 미치는 영향**: 안내를 따라 알림 설정에 들어가 카테고리를 켜도
알림이 오지 않는다. 원인을 잘못 알려주는 안내는 없느니만 못하다.

**수정 방향**: 권한 상태를 확인해 원인별로 다른 안내와 다른 행동을 준다.
권한이 거부됐으면 **시스템 설정으로 가는 경로**를, 카테고리가 꺼져 있으면
앱 안 알림 설정으로 가는 경로를.

### B3. 알림 설정 화면의 예약 건수도 권한 거부를 구분하지 못한다

**증거**: `docs/audit-evidence/device/08-notif-settings.png` —
권한이 거부된 상태에서도 "예약된 알림이 없습니다. 팀을 팔로우하거나 경기에서
알림을 켜면 예약됩니다." 라고만 말한다. 팔로우해도 오지 않는다.

**수정 방향**: B2 와 같은 판정을 공유한다. 같은 사실을 두 화면이 다르게
말하지 않도록 판정 로직을 한 곳에 둔다.

## 2. 디자인 변경

### D1. "내용 없음"을 시스템으로 다룬다

B1 을 고치는 김에, 지금 제각각인 빈 상태를 한 가지 규칙으로 정리한다.

현재는 세 가지가 섞여 있다.

1. 아무것도 안 그림 (`SizedBox.shrink()`) → **헤더만 남는 버그**
2. `WbEmptyState` 로 안내 (예: 마이야구 팀 미설정)
3. 헤더 없이 카드만

**규칙**:

- **없어도 되는 것**은 헤더까지 통째로 숨긴다. 예: 공식 영상이 아직 없음.
- **없다는 사실이 정보인 것**은 헤더와 함께 목적 있는 빈 상태를 보여준다.
  예: "이번 주말 우리 지역 경기 없음" 은 사용자가 알아야 할 답이다.

이 구분을 모듈 정의(`HomeModule`)에 데이터로 둔다. 화면 코드에서 판단하면
모듈마다 갈린다.

### D2. 처음 연 입문자의 홈이 비어 보이지 않게 한다

**증거**: 검수 대장 도입 후 데모 리캡이 `pending` 이 되어 화면에서 빠졌다
(의도된 동작). 그 결과 입문자 홈은 화제 주제 1개와 빈 섹션들만 남는다.

**수정 방향**: 콘텐츠가 없을 때 홈이 **무엇을 할 수 있는지** 로 채워지게 한다.
이미 있는 것들(입문 가이드 3건, 근처 경기, 팀 찾기)을 활용하고, **없는 것을
있는 것처럼 만들지 않는다.** 새 데이터를 만들어내는 방식은 금지.

## 3. 사용성 변경

### U1. 경기 탭이 경기 없는 날로 열린다

**증거**: `22-back-from-detail.png` — 경기 탭이 오늘(8/30)로 열리고
"이 날짜에는 경기가 없습니다". 측정값에서도 입문자의 다음 경기 상세 도달이

**수정 방향**: 세션에서 처음 경기 탭을 열 때, 오늘에 경기가 없으면 **가장 가까운
경기일로 착지**한다. `오늘로` 복귀 수단은 앱바에 **이미 있다**(tooltip `오늘로`).
사용자가 직접 고른 날짜는 그대로 존중한다 — 자동 이동은 최초 진입에만.

**측정**: `task_benchmark_test.dart` 의 `T1′` 탭 수가 줄어드는지 확인하고
`docs/task-benchmarks.md` 표를 실측값으로 갱신한다.

### U2. 팀 상세에서 홈 구장이 네 번째 섹션에 있다

**증거**: 측정값 `M2 팀 다음 경기·구장 taps=2 scrolls=2`.
섹션 순서는 다음 경기 → 최근 결과 → 참가 대회 → 주 활동 구장.

**수정 방향**: 팀 헤더 영역에 홈 구장을 한 줄로 노출한다. 아래의 `주 활동 구장`
섹션은 지도·길찾기까지 담고 있으므로 **그대로 둔다** — 요약을 위로 올리는 것이지
정보를 옮기는 것이 아니다.

**측정**: `M2` 의 스크롤 수가 줄어드는지 확인하고 문서를 갱신한다.

### U3. 권한 거부 이후로 나가는 길이 없다

B2·B3 의 사용성 쪽 대응. 권한이 거부된 상태에서 사용자가 스스로 복구할 수
있어야 한다. 앱은 권한을 다시 요청할 수 없으므로(안드로이드가 막는다)
**시스템 설정 화면으로 보내는 것이 유일한 길**이다.

# 2차 라운드 (2026-08-30, 이어서)

1차 수정을 검증하다 세 가지가 더 나왔다. 모두 "화면에는 있는데 데이터가 닿지
않는" 같은 종류의 문제였다.

## 1. 개인 기록 순위에 데이터가 한 번도 도달하지 않았다

**증거**: `batting_stats`, `pitching_stats` 테이블의 행 수가 **0**.
스키마·DTO·동기화 경로·저장소 집계·화면·단위 테스트가 **전부 존재**하는데,
그 테이블을 채우는 것이 파이프라인에 없었다. 순위표는 영구히 빈 화면이었고,
규정 타석·동률 규칙은 합성 객체로만 검증되고 있었다.

**수정**: 종료된 데모 경기에 박스스코어를 생성한다
(`_box_score` in `scripts/publish/build_seed.py`). 경기 id로 시드를 고정해
재생성해도 같은 값이 나온다. 데모 로스터를 4개 팀에서 **8개 팀 전부**로 넓혀
대부분의 경기가 기록을 갖게 했다.

**정합성**: 사실성이 아니라 검산 가능성을 목표로 했다.
- 타자 득점 합 = 팀 점수
- 상대 투수 실점 합 = 팀 점수
- 안타 ≤ 타수, 장타 합 ≤ 안타, 자책점 ≤ 실점

검증기에 이 규칙들을 넣고, 일부러 값을 망가뜨려 실제로 잡는지 확인했다.

**결과**: 타격 180줄, 투구 35줄, 8개 부문, 72명 랭킹. 동률이 `공동`으로 표시되고
`규정 타석 10 이상`·`11경기 중 10경기 집계`가 함께 나온다.

## 2. 데모로 계산한 순위가 데모가 아니라고 말했다

**증거**: `competition_repository.dart` 가 순위표의 출처를 `derived` 로
하드코딩하면서 `isDemo` 를 기본값 `false` 로 뒀다. 바탕이 전부 데모 경기인데
집계 결과는 진짜인 척했다.

**수정**: 집계에 기여한 경기에서 전파한다. 하나라도 데모면 순위표도 데모이고,
화면에 `데모 데이터로 계산한 순위` 배지가 붙는다.

지금은 선수 이름이 `데모선수 N-M` 이라 눈에 띄지만, 실제 데이터가 옆에 들어오면
그 단서가 사라진다. 그때를 위한 수정이다.

## 3. 로딩과 "비어 있음"을 같은 것으로 취급했다

**증거**: `player` 모드 홈에서 `리그 현황`·`기록 부문 선두` 가 데이터가 있는데도
나타나지 않았다.

**원인**: `ref.watch(x).value` 는 로딩 중에도 null 이다. 모듈은 그것을 "보여줄
것이 없음" 으로 읽고 섹션을 접었다. 비동기 홉이 두 번인 모듈은 특히 자주 걸렸다.
1차에서 헤더까지 숨기게 만들었으므로, 이 혼동은 페이지가 통째로 들썩이는
문제로 커졌을 것이다.

**수정**: `_moduleAsync` 헬퍼가 `loading` 과 `data` 를 구분한다. 로딩 중에는
헤더를 유지하고 스켈레톤을 그리고, **결과가 확정된 뒤 비어 있을 때만** 접는다.

**결과** (시드 데이터 기준, 렌더링되는 모듈 수):

| 모드 | 이전 | 이후 | 남은 숨김 |
| --- | ---: | ---: | --- |
| discover | 8/10 | 8/10 | 방송 리캡(검수 전), 공식 영상(데이터 없음) |
| player | 6/9 | **8/9** | 공지(데이터 없음) |
| both | 7/9 | **8/9** | 방송 리캡(검수 전) |

이제 숨겨진 모듈은 **전부 데이터가 실제로 없어서** 숨겨진다.
