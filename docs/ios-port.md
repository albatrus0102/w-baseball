# iOS 확장 가이드

> **현재 상태: iOS로 빌드해본 적이 없습니다.**
>
> `ios/` 디렉터리는 Flutter가 만든 기본 상태이고, macOS와 Xcode가 없는
> 환경에서 작업했으므로 컴파일·실행·검증 모두 하지 않았습니다.
> 아래는 확인해야 할 것들의 목록이지, "이미 동작한다"는 보고가 아닙니다.

우선순위상 iOS는 Android 다음입니다. 다만 **iOS를 막는 결정을 하지 않았습니다** —
플랫폼 분기 코드가 없고, 모든 로직이 Dart에 있으며, `dart:io` 직접 의존이
없습니다.

---

## 1. 의존성 점검

전부 iOS를 지원하는 패키지입니다. 다만 설정이 필요한 것들이 있습니다.

| 패키지 | iOS 지원 | 추가 작업 |
| --- | --- | --- |
| `drift` + `drift_flutter` | 예 | 없음. SQLite는 iOS 기본 제공 |
| `path_provider` | 예 | 없음 |
| `shared_preferences` | 예 | `NSUserDefaults` 로 매핑됨 |
| `dio` | 예 | ATS(App Transport Security) — HTTPS만 쓰면 문제없음 |
| `flutter_local_notifications` | 예 | **권한 요청 방식이 다름** (3절) |
| `timezone`, `flutter_timezone` | 예 | 없음 |
| `url_launcher` | 예 | **`LSApplicationQueriesSchemes` 필요** (2절) |
| `share_plus` | 예 | iPad에서 팝오버 앵커 필요 |
| `webview_flutter` | 예 | `WKWebView` 사용. 허용 목록 로직은 그대로 |
| `package_info_plus` | 예 | 없음 |
| `cached_network_image` | 예 | 없음 |

## 2. `Info.plist` 에 넣어야 할 것

### 위치 (선택 기능)

```
NSLocationWhenInUseUsageDescription
  근처에서 열리는 경기를 찾는 데만 사용합니다. 위치는 기기 안에서만 계산하며
  서버로 보내지 않습니다.
```

**`NSLocationAlwaysAndWhenInUseUsageDescription` 은 넣지 마세요.**
백그라운드 위치를 쓰지 않습니다. 문구를 넣으면 심사에서 근거를 요구받고,
쓰지도 않는 권한을 설명해야 합니다.

이 문구는 **거절해도 앱이 온전히 동작한다**는 사실과 일관돼야 합니다.
근처 경기는 지역(시·도) 선택만으로 동작합니다.

### 외부 앱 열기

`url_launcher` 로 지도·캘린더를 열려면 조회할 스킴을 선언해야 합니다.

```
LSApplicationQueriesSchemes
  - comgooglemaps
  - nmap        (네이버 지도)
  - kakaomap
```

선언하지 않으면 `canLaunchUrl` 이 조용히 `false` 를 돌려주고, 사용자에게는
버튼이 아무것도 안 하는 것처럼 보입니다.

### 사진·마이크·연락처

**필요 없습니다.** 넣지 마세요. 쓰지 않는 권한 문구는 심사 지연 사유입니다.

## 3. 알림

iOS는 Android와 권한 모델이 다릅니다.

- 권한 요청 시점이 더 중요합니다. **온보딩에서 묻지 않는다**는 현재 정책이
  iOS에서는 더 유리합니다 (거절 후 재요청이 사실상 불가능하므로).
- `flutter_local_notifications` 의 iOS 초기화에서
  `requestAlertPermission: false` 등으로 **자동 요청을 끄고**, 사용자가 알림을
  켜는 시점에 명시적으로 요청하세요. 기본값으로 두면 앱 시작 시 팝업이 뜹니다.
- 예약 알림에 시간대가 필요합니다. `flutter_timezone` 이 이미 붙어 있습니다.
- **방해 금지 시간 계산은 플랫폼 무관**입니다 (`NotificationPlanner` — 순수 함수,
  단위 테스트 있음). 그대로 동작해야 합니다.
- `notificationId()` 가 결정적이므로 재예약 시 쌓이지 않고 교체됩니다. iOS의
  64개 예약 한도를 고려하면 이 성질이 중요합니다. **한도를 넘지 않는지
  확인하세요** — 30일 일정판 × 여러 카테고리면 넘을 수 있습니다.

## 4. 폰트

`Pretendard` 를 쓰고 있고 한국어 폴백이 있습니다.

- iOS 시스템 한국어 폰트(Apple SD Gothic Neo)와 **메트릭이 다릅니다.**
  줄 높이와 자간이 달라져 레이아웃이 미묘하게 변합니다.
- 폰트를 번들한다면 **라이선스를 확인**하세요 (Pretendard는 SIL OFL).
- 번들하지 않고 폴백에 맡긴다면, 4가지 화면 크기 검사를 iOS에서 다시 돌리세요.
  현재 넘침 검사는 Android 메트릭 기준입니다.

## 5. UI 확인 항목

- **안전 영역** — 노치와 홈 인디케이터. 하단 탭바가 홈 인디케이터와 겹치지
  않는지 확인.
- **뒤로 가기** — iOS에는 시스템 뒤로 가기 버튼이 없습니다. 전체 화면 라우트
  (검색·상세)에 화면 내 뒤로 가기가 있는지, 스와이프 백이 동작하는지 확인.
- **다크 모드** — `ThemeMode.system`. iOS 설정과 연동되는지 확인.
- **동적 글자 크기** — iOS의 Dynamic Type. 현재 0.85~1.4배 클램프가 iOS에서도
  적용되는지 확인.
- **iPad** — 지원할 생각이 없으면 아이폰 전용으로 선언하세요. 지원한다면
  480dp 초과 폭에서 레이아웃을 다시 봐야 합니다 (`WbBreakpoint.expanded`).

## 6. 심사에서 물어볼 것

- **데모 데이터** — 실제 기록이 아님을 앱 안과 스토어 설명 양쪽에 명시.
  "실제 데이터인 척하는 앱"으로 오해받지 않게.
- **개인정보 라벨(App Privacy)** — 수집 항목 없음. 위치는 "앱 기능"으로
  선택 사용, 기기 밖으로 나가지 않음.
- **최소 기능성** — 콘텐츠가 웹사이트 링크 모음처럼 보이면 거절 사유가 됩니다.
  로컬 DB·오프라인 동작·일정판·알림이 있으므로 설명에 이를 명시하세요.
- **제3자 콘텐츠** — 뉴스는 제목과 링크만 저장하고 본문을 복제하지 않는다는
  점을 설명할 수 있어야 합니다.

## 7. 작업 순서

1. macOS + Xcode 준비, `flutter doctor` 로 iOS toolchain 확인
2. `flutter build ios --debug --no-codesign` — **먼저 컴파일부터** 통과시키기
3. 시뮬레이터에서 실행, 전 화면 순회
4. `Info.plist` 문구 추가 (2절)
5. 알림 초기화에서 자동 권한 요청 끄기 (3절)
6. 실기기에서 알림·위치·외부 링크 확인
7. 폰트와 안전 영역 확인, 넘침 검사를 iOS에서 재실행
8. `flutter build ipa` 후 TestFlight
