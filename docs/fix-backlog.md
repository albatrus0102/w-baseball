- **실제 증거**: `ProgramSeason.nextAirSlot` 은 편성 슬롯(목 22:00)에서 다음
  방송을 계산하는데, 이 슬롯에는 만료가 없습니다. 모델에는 `finaleDate` 와
  `isActive` 처리가 **이미 올바르게 들어 있는데**, 시드가 둘 다 쓰지 않습니다 —
  `assets/seed/content/discover.json` 의 시즌은 `isActive: true` 이고
  `finaleDate` 가 없습니다. 화제 주제 3건도 `activeFrom`/`activeUntil` 이
  전부 비어 있습니다.
- **사용자에게 미치는 영향**: 종영 후에도 홈 상단이 `다음 방송 9월 3일 (목)
  오후 10:00` 이라고 **단언**합니다. 이건 존재하지 않는 방송에 대한 미래
  주장이고, 상시 제약("데이터가 없다는 이유로 실제처럼 보이는 방송 결과를
  만들어내서는 안 된다")에 정면으로 걸립니다. 몇 년이 지나도 자동으로 멈추지
  않습니다 — 두 필드 모두 시즌을 발행할 때 한 번 쓰이고 다시 수정되지 않기
  때문입니다.
- **수정**: 근거가 있을 때만 말합니다. `nextAirSlot` 이
  `lastAiredAtKst` 를 받아, `finaleDate` 가 없으면 최근 방영분(없으면 편성일)이
  **3주(슬롯 3회) 안**일 때만 다음 슬롯을 반환합니다. 종영일이 명시돼 있으면
  그쪽이 더 강한 근거이므로 기존 동작을 그대로 둡니다. 실제 종영일을 모르는
  상태에서 날짜를 지어내지 않는 것이 이 방식의 요점입니다.
- **수정 후 검증**: `test/unit/air_schedule_test.dart` (신규) 9건 — 경계 20일/
  22일, 방영 전 편성일 근거, 근거 없음, 종영일 우선, 보관된 시즌, 편성 정보
  없음. 골든은 변하지 않습니다(시드의 최신 회차 8/26 이 기준 시각 8/30 에서
  3주 안).
- **남은 데이터 쪽 과제**: 시드의 시즌 설명문("채널A · 매주 목요일 밤 10시")은
  현재형 주장이고, 화제 주제에는 `activeUntil` 이 없습니다. 둘 다 실제 편성
  종료 시점을 알아야 고칠 수 있으므로 **여기서 만들어 넣지 않았습니다.**
  발행 시 채워야 할 항목으로 남깁니다.

### [A-9] [완료] `visibility` 는 개인정보 통제 장치인데 아무 일도 하지 않았다

- **실제 증거**: 모든 엔티티와 모든 콘텐츠 레코드가 `RecordVisibility` 를
  가집니다. 페이로드에서 파싱되고, (엔티티는) SQLite 에 저장되고, 도메인
  모델까지 올라옵니다. 그리고 **어떤 저장소도 이걸로 거르지 않고 어떤 화면도
  보지 않습니다.** `grep -rn "RecordVisibility" lib/features lib/data/repositories`
  → 결과 0건.
- 콘텐츠 쪽은 한 단계 더 나갑니다. `content_sync.dart` 의 **쓰기 지점 11곳이
  `visibility` 를 아예 기록하지 않아** 모든 콘텐츠 행이 컬럼 기본값
  `'public'` 으로 저장됐습니다. 발행자가 `private` 로 표시해도 값이 DB 에
  도달조차 하지 않습니다.
- **사용자에게 미치는 영향**: 지금 시드에는 비공개 레코드가 없으므로 **유출은
  없습니다.** 그러나 통제 장치가 연결되어 있지 않은 상태는 터지는 버그보다
  나쁩니다 — 처리된 것처럼 보이기 때문입니다. 발행 측이 이 필드를 믿고 무언가를
  비공개로 내보내는 순간 그대로 노출됩니다.
- **수정**:
  - 엔티티: `SyncEngine` 의 쓰기 경로에서 제외(`_visibleOnly`). 읽기 경로가 열
    곳이고 쓰기 경로가 한 곳이며, 스냅샷의 present 집합에서 빠지면 기존 tombstone
    처리가 이미 저장된 행을 삭제 표시합니다 — 레코드가 회수됐을 때 필요한 동작이
    정확히 그것입니다.
  - 콘텐츠: 쓰기 11곳에 `visibility` 를 기록하고, `ContentMeta.isPublishable`
    (A-4 에서 읽기 경로 7곳에 이미 연결해 둔 관문)에서 확인.
  - 알 수 없는 값은 `public` 으로 읽습니다. 오타가 앱을 통째로 비우면 안 되고,
    발행자가 **명시적으로** 감춘 것만 감춥니다.
- **수정 후 검증**: `test/unit/visibility_test.dart` (신규). 시드의 실제 레코드
  하나에 `visibility` 를 다시 써 넣고 동기화까지 태워, 발행 페이로드와 같은
  경로를 지나게 합니다.
- **남은 것**: `content_sync.dart` 는 `qualityStatus`, `verifiedAt`,
  `contentHash`, `sourceRecordId` 도 여전히 버립니다. 앞의 둘은 **가장 약한
  주장**으로 기본값이 잡히므로 잃는 방향이 안전한 쪽이고(아는 것보다 덜 말함),
  되살리면 검증이 없는 경로로 페이로드가 "사람이 확인함"을 주장할 수 있게
  됩니다. 그래서 지나가는 김에 고치지 않고 항목으로 남깁니다.
