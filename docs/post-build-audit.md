#### 런타임에서만 드러난 결함 2건

**(1) 딥링크가 라우터에 도달하지 않았다.**
매니페스트에 intent-filter는 있었지만 `flutter_deeplinking_enabled` 메타데이터가
없어, OS는 앱을 실행시키되 **경로를 버렸습니다.** 공유 링크가 전부 홈으로
열렸습니다. `logcat` 에 인텐트는 보이는데 라우팅 흔적이 없어 확인했습니다.
위젯 테스트는 `router.go()` 를 직접 호출하므로 이 경계를 넘지 않아 통과했습니다.

**(2) 알림 탭이 백그라운드 복귀 시 무시됐다.**
대기 중인 목적지를 위젯 `build` 안에서 꺼내도록 만들었는데, 백그라운드에서
복귀할 때는 셸이 다시 빌드되지 않습니다. 값을 아무도 읽지 않아 홈이 열렸습니다.
`ValueNotifier` + 리스너로 바꿔 해결했습니다.

**(3) 데모 표시가 스크린리더에 읽히지 않았다.**
경기 카드에는 `데모` 배지가 보이지만 시맨틱 라벨에는 없었습니다. TalkBack을 켜고
덤프해서야 드러났습니다. 데모 라벨은 이 앱의 핵심 안전장치인데, 그것을 볼 수 없는
사용자에게만 알려주지 않고 있었습니다. 라벨에 추가하고 회귀 테스트를 붙였습니다.

**(4) 알림 설정 부제가 토글과 모순됐다.**
전부 꺼져 있는데 "…알림을 켜 두셨습니다"로 표시됐습니다. 알림 본문용 `reasonKo`를
설정 부제로 재사용한 탓입니다. `descriptionKo`를 분리했습니다.

네 건 모두 **코드 검토와 위젯 테스트를 통과한 상태**였습니다. 게이트 2가
형식적 절차가 아니라는 증거입니다.

#### 관찰했지만 앱 결함으로 보지 않은 것

부팅 직후 뒤로가기 테스트에서 ANR("여자야구 isn't responding")이 한 번
발생했습니다. 앱 결함으로 보고하지 않은 이유는 다음과 같습니다.

- ANR 사유가 `Input dispatching timed out (Application does not have a focused
  window)` — 창이 아직 준비되지 않은 상태였습니다.
- 같은 시각 **`system_server` 자체가 프레임 174개를 흘리고** 있었고
  (`Slow dispatch took 2823ms`), 앱만의 문제가 아니었습니다.
- 45초 안정화 후 동일 절차를 반복하니 ANR 0건으로 정상 동작했습니다.

**소프트웨어 GPU 에뮬레이터의 콜드 부팅 아티팩트로 판단**하되, 실기기에서
재확인하기 전까지 완전히 배제하지는 않습니다.

#### 성능은 여전히 UNVERIFIED

헤드리스 에뮬레이터는 소프트웨어 GPU(swiftshader)로 렌더링합니다. 측정값

### Q2. 배포하면 가장 먼저 이탈할 사용자는 누구이며 이유는?

**방송을 보고 링크를 받아 설치한 입문자.** 두 가지가 연달아 무너집니다.

1. 공유 링크로 들어오면 온보딩으로 튕기고 **목표 경기를 잃습니다.**
   프로브 결과: `PROBE|fresh|onboarding=1|detail=0`
   (설정을 마친 사용자는 `detail=1`로 정상)
2. 온보딩을 마치고 발견 탭에 도착해도 **콘텐츠가 14건뿐**이고, 그중 뉴스는
   이야기 묶음 1건입니다. 다시 열 이유가 만들어지지 않습니다.

### Q3. 입문자가 60초 안에 흥미를 느낄 수 있는가?

**부분적으로만.** 구조는 맞습니다 — 입문자 홈은 `지금 화제 → 방송 다시 보기 →
이번 주말 가까운 경기` 순으로 점수를 아래로 내렸고(`home_modules.dart:80-92`),
스크린샷에서 확인됩니다.

그러나 그 자리에 들어갈 **내용물이 없습니다.** 화제 주제 3건, 가이드 3건,
뉴스 묶음 1건, 데모 회차 1건이 전부입니다. 60초 중 50초는 볼 것이 없습니다.

### Q4. 현역 사용자가 경기 전마다 다시 열 실용성이 있는가?

**설계는 그렇고, 지금은 아닙니다.** 홈 첫 화면에서 다음 경기 상세까지 1탭,
스크롤 0 (측정값). 30일 일정판·날씨·순위가 모두 홈 상단에 있습니다.

막는 것: **알림을 눌러도 아무 데도 가지 않습니다.**
`lib/core/platform/notification_service.dart` 의 `initialize()` 가
`onDidReceiveNotificationResponse` 를 등록하지 않아, `payload` 는 담기지만
(`:253`) 아무도 읽지 않습니다. "경기 1시간 전" 알림을 눌러도 홈이 열립니다.

### Q5. 현재 홈의 정보 우선순위가 두 사용자군에 맞는가?

**예.** 모드별 순서가 데이터로 분리되어 있고 선두 모듈은 접히지 않습니다
(`home_modules.dart:99-116`). `둘 다` 모드는 두 목록을 이어붙이지 않고 10개로
유지합니다 — 우려했던 "두 배로 긴 홈"이 아닙니다.

### Q6. 야구여왕2에서 실제 여자야구로 자연스럽게 이동하는가?

**구조는 PASS, 콘텐츠는 FAIL.** `FeaturedTopic`/`Program`/`Season`/`Episode`로
일반화되어 있어 시즌 종료 후 다른 대회로 교체 가능합니다. 실제로 WBSC 월드컵이
같은 형태로 들어가 있습니다.

그러나 방송에서 실제 경기로 잇는 다리가 **데모 회차 1건**뿐이고, 그 회차는
`isDemo: true` 입니다. 즉 지금 상태에서 방송 → 실제 야구 이동은 **한 번도
실제 데이터로 이어지지 않습니다.**

### Q7. 근처 경기를 찾아 관람 준비까지 할 수 있는가?

**대체로 예. 마지막 한 걸음이 빠집니다.**

- 위치 권한 없이 발견 → 근처 경기까지 **2탭, 스크롤 0** (측정값)
- `useDeviceLocation == false` 상태에서 정상 동작 (테스트로 고정)
- 캘린더·길찾기·공유가 경기 상세 한 행에 있음

빠진 것: **공식 근거 확인.** 23경기 전부 `officialDetailUrl` 이 없어
"공식 기록 페이지 열기" 버튼이 **한 번도 렌더링되지 않습니다.**
화면은 "아직 수집되지 않았습니다"라고 정직하게 말하지만, 마스터 명세의
과업 4(공식 원문 확인 후 복귀)는 현재 데이터로 **완료 불가**입니다.

### Q8. 일정·날씨·순위·개인 기록을 믿을 수 있는가?

| 영역 | 판정 | 근거 |
| --- | --- | --- |
| 날씨 | **신뢰 가능** | D+10/D+11 경계가 자동 테스트로 고정. 범위 밖은 값 자체를 만들지 않음 |
| 개인 기록 | **신뢰 가능** | 규정 타석 비례 계산, 동률 공유 순위, 종합 평점 부재를 테스트가 강제 |

개인 기록에는 동률 테스트가 있는데 **팀 순위에는 계산도 테스트도 없다**는
비대칭이 이 앱에서 가장 놓치기 쉬운 구멍입니다.

### Q9. 공식 API 연결 시 화면·도메인을 다시 만들어야 하는가?

**아니오.** 이건 이 저장소에서 가장 잘 된 부분입니다.

`test/contract/adapter_equivalence_test.dart` 가 정적 파일 원천과 페이지네이션
REST 원천이 **동일한 도메인 지문**을 만드는지 검증하고 통과합니다.
UI에서 Dio·JSON 경로·SQL 참조를 찾지 못했습니다. 어댑터 교체는 원천 계층 한
곳입니다.

### Q10. 인터넷·원천·API가 실패해도 유용한가?

**코드 수준 PASS, 런타임 UNVERIFIED.**

동기화 실패 격리, 404 처리, 상위 스키마 수신 시 캐시 보존, 재개, tombstone이
모두 테스트로 검증됩니다. UI는 DB만 봅니다.

그러나 **실제 기내 모드 실행을 못 했습니다.** "첫 화면 전에 네트워크를
기다리지 않는가"는 코드상 그렇지만(부트스트랩이 DB를 먼저 그림) 육안 확인
미완입니다. 또 **checksum 불일치 시나리오 테스트가 없습니다.**

### Q11. 디자인이 독립 제품처럼 완성되어 있는가?

**대체로 예.** 21장의 골든 스크린샷과 토큰 시스템을 확인했습니다. 분홍·리본
관용구를 피했고, 밀도 두 종류가 컴포넌트가 아니라 컨텍스트로 내려갑니다.
데모 배지가 목록·상세 양쪽에 붙습니다.

결함: **현역 홈이 앱 자체 최대 글자 배율(1.4x)에서 넘칩니다.** 기존 테스트는
1.3까지만 봐서 놓쳤습니다.

## 9~10단계 요약 (API 교체 · 오프라인)

API 교체 가능성은 **이 프로젝트의 최대 강점**입니다. 계약 동등성 테스트가
존재하고 통과하며, pagination·delta·멱등 upsert·tombstone·정정 이력·스키마
버전 거부·재개·마이그레이션 보존이 모두 개별 테스트로 검증됩니다.
