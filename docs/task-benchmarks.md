# 대표 과업 측정

## 왜 측정하는가

"편리하다"는 감상은 검증이 아닙니다. 대표 과업 5개를 정하고, 위젯 테스트에서
**실제 라우터를 콜드 스타트부터 구동해** 탭 수와 스크롤 수를 셌습니다.

측정 코드: `test/widget/task_benchmark_test.dart` (17개 테스트)

과업은 두 묶음입니다.

- **T1~T5** — 개정 명세가 요구한 두 사용자군(입문자·현역) 기준 과업
- **M1~M5** — 최초 명세가 이름으로 지목한 과업

겹치지 않으므로 둘 다 측정합니다.

```bash
flutter test test/widget/task_benchmark_test.dart --reporter=expanded
```

테스트가 측정값을 이렇게 출력합니다.

```
BENCHMARK|T1 현역 다음 경기 상세|taps=1|scrolls=0
BENCHMARK|T1 입문자 경기 상세|taps=2|scrolls=0
BENCHMARK|T2 검색 (홈)|taps=1|scrolls=0
BENCHMARK|T2 검색 (발견)|taps=1|scrolls=0
BENCHMARK|T2 검색 (경기)|taps=1|scrolls=0
BENCHMARK|T2 검색 (마이야구)|taps=1|scrolls=0
BENCHMARK|T3 근처 경기|taps=2|scrolls=0
BENCHMARK|T4 내 팀 설정|taps=2|scrolls=0
BENCHMARK|T5 마이야구 진입|taps=1|scrolls=0
BENCHMARK|M1 오늘 경기 결과|taps=2|scrolls=0
BENCHMARK|M2 팀 다음 경기·구장|taps=2|scrolls=0
BENCHMARK|M3 대회 순위|taps=2|scrolls=0
BENCHMARK|M4 원문 확인 후 복귀|taps=2|scrolls=0
BENCHMARK|M5 캘린더+알림 (상세 도달)|taps=1|scrolls=0
```

**이 문서의 표는 위 출력을 옮긴 것입니다.** 네비게이션이 나빠지면 테스트가
먼저 실패하므로, 문서와 코드가 조용히 어긋날 수 없습니다.

`scrolls=0` 은 "첫 화면 안에서 다음 탭 지점에 닿는다"는 뜻입니다.
`scrollsToReach()` 가 대상이 이미 히트테스트 가능한지 확인하고, 아니면 한 번에
400px씩 끌면서 셉니다. 10번 안에 못 찾으면 `-1` 을 돌려주므로,
**경로가 깨졌을 때 "스크롤 0"으로 위장되지 않습니다.**

### M2 가 2스크롤에서 0으로 바뀐 이유

팀 상세의 `주 활동 구장` 섹션은 네 번째에 있어 스크롤이 2회 필요했습니다.
팀 헤더에 홈 구장을 한 줄로 요약해 올렸습니다. **아래 섹션은 그대로 둡니다** —
지도와 길찾기를 담고 있으므로, 정보를 옮긴 것이 아니라 답을 위로 꺼낸 것입니다.

### M3 이 마이야구가 아니라 검색인 이유

마이야구의 `리그 현황` 모듈은 **팀을 팔로우한 뒤에만** 렌더링됩니다. 팔로우한
사용자에게는 `마이야구 → 리그 현황` 2탭이지만, 아직 아무것도 팔로우하지 않은
사용자도 이 과업을 할 수 있어야 하므로 **누구에게나 되는 경로**를 측정했습니다.

이 과업을 측정하다가 실제 버그를 찾았습니다: 검색 결과의 대회를 누르면 항상
"대회를 찾을 수 없습니다"가 떴습니다. 검색이 **대회 id** 를 넘기는데 화면은
**시즌 id** 로 조회하기 때문이었습니다. 대회는 여러 해에 걸쳐 있어 자체 순위가
없으므로 화면 쪽이 옳고, 검색이 최신 시즌 id를 넘기도록 고쳤습니다
(`lib/data/repositories/search_repository.dart`). 회귀 테스트로
"대회를 찾을 수 없습니다"가 뜨면 실패하게 했습니다.

### T1′ 이 3탭에서 2탭으로 바뀐 이유

측정한 날(2026-08-30) 데모 일정에 경기가 없어, 경기 탭이 빈 날짜로 열리고
`다음 경기일` 을 한 번 더 눌러야 했습니다. **그 날에 가짜 경기를 넣어 숫자를
고치지 않았습니다.** 대신 경기 탭이 처음 열릴 때 오늘에 경기가 없으면 가장 가까운
경기일로 착지하도록 바꿨습니다.

착지는 **조용히** 일어나지 않습니다. 화면 상단에 "오늘은 경기가 없어 8월 31일
일정을 보여드립니다" 와 `오늘로` 버튼이 함께 나옵니다. 사용자가 직접 날짜를 고른
뒤에는 앱이 다시 옮기지 않습니다 — 계속 위치를 다시 정하는 앱은 처음부터 엉뚱한
곳에 있는 앱보다 나쁩니다.

## 네트워크 실패 시 대체 동작

| # | 과업 | 오프라인 / 동기화 실패 시 |
| --- | --- | --- |
| T1 | 다음 경기 상세 | 로컬 DB의 마지막 일정이 그대로 보입니다. 마지막 갱신 시각을 표시해 얼마나 오래됐는지 알립니다. 빈 화면 없음 |
| T1′ | 경기 목록 | 동일. 날짜 이동·필터 전부 로컬 쿼리 |
| T2 | 통합 검색 | **영향 없음.** 검색은 100% 로컬 (초성 색인 포함) |
| T3 | 근처 경기 | **영향 없음.** 지역 코드 기준 로컬 필터. 위치 권한도 네트워크도 불필요 |
| T4 | 내 팀 설정 | **영향 없음.** 팀 목록은 로컬, 팔로우도 로컬 저장 |
| T5 | 마이야구 | 일정판은 로컬. **날씨만 비어 있고**, 그 사실을 명시합니다 (가짜 예보를 만들지 않음) |
| M1 | 오늘 경기 결과 | 로컬 결과를 그대로 표시. 마지막 갱신 시각으로 신선도를 알림 |
| M2 | 팀 다음 경기·구장 | 팀 상세 전체가 로컬. 영향 없음 |
| M3 | 대회 순위 | 순위는 로컬. 값이 오래됐을 수 있다는 사실만 표시 |
| M4 | 공식 원문 확인 | **원문만** 네트워크가 필요합니다. 열리지 않아도 목록 위치·필터·날짜는 그대로 유지 |
| M5 | 캘린더 추가·알림 설정 | 둘 다 기기 로컬 동작. 영향 없음 |

공통 규칙:

- UI는 DB만 봅니다. 네트워크 실패는 **화면 상태가 아니라 갱신 시각**에 나타납니다.
- 일부 원천이 실패해도 성공한 원천은 반영됩니다. 전체 롤백하지 않습니다.
- 사용자 소유 데이터(팔로우·저장·참석·예약 알림)는 동기화와 무관합니다.

## 함께 검증한 것

### 문맥 보존

경기 탭에서 `국내` 필터를 걸고 → 발견 탭 → 경기 탭으로 돌아왔을 때
필터가 유지되는지 확인합니다. `StatefulShellRoute.indexedStack` 덕분입니다.

### 알림이 실제로 예약되는지

M5의 두 번째 테스트는 상세에서 `알림` 을 켠 뒤, 그 경기가 실제로 예약 대상
집합에 들어갔는지 데이터베이스에서 확인합니다. 버튼이 눌리는 것과 알림이
예약되는 것은 다른 문제입니다.

### 위치 권한 없이 동작

T3 경로를 `useDeviceLocation == false` 상태에서 끝까지 진행하고,
지역 칩(`전체 지역`)이 권한 없이 렌더링되는지 확인합니다.
**위치 권한은 근처 경기의 전제 조건이 아닙니다.**

## 측정하지 않은 것

정직하게 적습니다.

- **실사용자 테스트를 하지 않았습니다.** 탭 수는 기계가 센 것이고, 사람이 그
  탭을 *찾는 데* 걸리는 시간은 다른 문제입니다. `docs/user-testing-plan.md` 는
  계획이지 결과가 아닙니다.
- **실기기 성능(프레임 드랍, 콜드 스타트 시간)을 측정하지 않았습니다.**
- **읽는 시간**을 재지 않았습니다. 탭이 적어도 화면이 이해 안 되면 소용없습니다.
- 측정은 **데모 데이터 기준**입니다. 실제 리그 규모에서는 목록이 길어져
  스크롤 수가 달라질 수 있습니다.

## 과업을 추가할 때

1. `task_benchmark_test.dart` 에 테스트를 추가하고 `record()` 로 출력하세요.
2. 실제 라우터를 콜드 스타트부터 구동하세요. 화면을 직접 `pumpWidget` 하면
   진입 경로가 측정에서 빠집니다.
3. **낙관적인 경로가 아니라 나쁜 경로**를 기준으로 재세요.
4. 이 문서의 표를 테스트 출력에서 옮기세요. 손으로 추정하지 마세요.
