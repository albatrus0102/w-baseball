# 사용성 점검 계획

> **이 문서는 계획입니다. 실사용자 테스트를 수행하지 않았습니다.**
>
> 아래 어떤 숫자도 실제 참가자에게서 나온 값이 아닙니다. 수행하기 전까지
> "사용자 테스트 결과 ○○%"라고 인용하면 안 됩니다.

지금까지 한 것은 두 가지입니다.

1. **기계 측정** — 위젯 테스트에서 탭 수와 스크롤 수 실측
   (`docs/task-benchmarks.md`)
2. **인지적 워크스루(cognitive walkthrough)** — 아래 3절. 사람 없이 설계자가
   각 단계에서 "사용자가 다음에 뭘 할지 알 수 있나"를 점검한 것

3번(실사용자 테스트)이 남아 있습니다.

---

## 1. 왜 기계 측정만으로는 부족한가

탭 수는 **경로의 길이**를 재고, 사용성은 **경로를 찾는 난이도**를 다룹니다.
둘은 다릅니다.

- 1탭이어도 그 버튼이 뭘 하는지 모르면 0탭이 됩니다.
- "데모" 배지를 보고 무슨 뜻인지 아무도 모른다면, 배지를 붙인 의미가 없습니다.
- 스포일러 설정은 **켜기 전에 그게 뭔지 알아야** 켭니다.

이런 것은 사람에게 물어야만 알 수 있습니다.

---

## 2. 검증할 가설

| # | 가설 | 반증 신호 |
| --- | --- | --- |
| H1 | 입문자는 홈 첫 화면에서 "볼 만한 것"을 찾는다 | 첫 화면에서 뭘 눌러야 할지 모른 채 3초 이상 머뭇거림 |
| H2 | 현역은 다음 경기와 비 소식을 1탭에 얻는다 | 홈이 아닌 다른 탭부터 찾음 |
| H3 | "데모" 배지의 뜻이 전달된다 | 실제 경기 기록이라고 답함 |
| H4 | 모드 선택이 "기능 제한"으로 오해되지 않는다 | "다른 모드 고르면 못 보는 게 있나요?"라는 질문 |
| H5 | 위치 권한 없이 근처 경기가 되는 걸 안다 | 권한을 찾아 헤매거나 기능을 포기함 |
| H6 | 밀도 설정이 "정보 숨김"으로 오해되지 않는다 | 조밀 모드를 껐다 켜며 뭐가 사라졌는지 확인하려 함 |
| H7 | 순위표 규정 충족 표기가 이해된다 | 규정 미달 선수가 왜 빠졌는지 묻지 못함 |
| H8 | 예보 범위 밖 표기가 "고장"으로 읽히지 않는다 | 30일 뒤 날씨가 안 나온다고 버그로 신고 |

H3, H4, H6, H8은 **이 앱이 정직하려고 한 선택들이 실제로 전달되는지**를 묻습니다.
정직한 설계가 혼란스럽게 전달되면 정직한 게 아닙니다.

## 3. 인지적 워크스루 (수행함 — 설계자 자체 점검)

각 단계에서 네 가지를 물었습니다: (a) 사용자가 이 목표를 갖고 있는가?
(b) 필요한 조작이 보이는가? (c) 그게 맞는 조작이라고 알아볼 수 있는가?
(d) 조작 후 진행됐다는 피드백이 있는가?

| 흐름 | 발견한 문제 | 대응 |
| --- | --- | --- |
| 온보딩 3단계 | 모드 이름이 기능 차단처럼 읽힐 위험 | 모드 라벨을 상태 서술문으로("여자야구를 하고 있어요"), 설정에 "표시 순서만 바뀝니다" 명시 |
| 경기 탭 · 경기 없는 날 | 빈 화면이 막다른 길 | 빈 상태에 `이전/다음 경기일` 버튼 (T1′ 측정에 반영됨) |
| 마이야구 30일판 | 30일치 날씨를 기대하게 만듦 | 예보 범위 밖은 날씨 칸 자체를 없애고 이유를 표기 |
| 날씨 배지 | 예보 "미저장"과 "범위 밖"이 같은 문구 | 범위 안이면 아무것도 표시하지 않도록 분리 |
| 팀 목록 지역 필터 | 필터가 팀을 전부 숨김 | 라벨이 아니라 지역 코드로 필터하도록 수정 |
| 밀도 설정 | "정보가 사라지나?" 오해 가능 | 설명문에 "어떤 정보도 사라지지 않습니다" 명시 + 테스트로 강제 |
| 스포일러 | 카드만 가리고 알림에서 노출 | 카드·상세·알림 전부에 적용 |

**이건 사람에게 물어본 결과가 아닙니다.** 설계자가 자기 화면을 점검한 것이므로,
설계자가 못 보는 것은 여전히 못 봅니다. 그래서 4절이 필요합니다.

## 4. 실사용자 테스트 계획 (미수행)

### 참가자

| 집단 | 인원 | 조건 |
| --- | ---: | --- |
| 입문자 | 5 | 여자야구 경기를 본 적 없음. 방송은 봤거나 안 봤거나 |
| 현역 | 5 | 사회인 여자야구팀 소속 (선수 또는 운영) |

5+5는 **발견 목적**의 최소선입니다. 통계를 내기 위한 수가 아니라 심각한 문제를
찾기 위한 수입니다. 비율(%)로 보고하지 마세요.

### 방법

- 1인 40분, 대면 또는 화면 공유
- 실기기 debug 빌드, **데모 데이터 그대로** (실제 기록이 아님을 사전 고지하지
  않음 — H3을 검증해야 하므로)
- 소리 내어 생각하기(think-aloud)
- 진행자는 **답을 알려주지 않습니다.** 막히면 막힌 지점을 기록합니다

### 과업 (docs/task-benchmarks.md 와 동일)

1. 이번 주말에 볼 만한 경기를 찾아보세요.
2. (현역) 우리 팀 다음 경기가 언제인지, 비가 오는지 확인하세요.
3. 서울 근처에서 하는 경기를 찾아보세요.
4. 응원할 팀을 하나 고르세요.
5. 화면에 보이는 이 기록이 실제 경기 결과인지 아닌지 말해주세요. **(H3)**
6. 결과를 미리 보고 싶지 않다면 어떻게 설정하겠습니까? **(H1, 스포일러)**
7. 글씨가 빽빽하다면 어떻게 바꾸겠습니까? **(H6)**

### 기록할 것

- 과업별 성공/실패/부분성공
- 실제 탭 수 — **측정값과의 차이가 곧 발견 난이도**
- 막힘 지점과 그때 한 말
- 잘못된 멘탈 모델 (특히 H3, H4, H6, H8)

### 판정 기준

- **심각**: 5명 중 2명 이상이 과업 실패 → 다음 릴리스 차단
- **보통**: 2명 이상이 막혔지만 결국 성공 → 다음 릴리스에서 수정
- **경미**: 1명 → 기록만

### 절대 하지 말 것

- 참가자 개인정보를 필요 이상으로 수집하지 마세요. 팀 소속 여부면 충분합니다.
- 녹화는 명시적 동의를 받고, 얼굴을 담지 마세요.
- 미성년자를 포함하지 마세요. 필요하면 보호자 동의 절차를 먼저 설계하세요.
- **결과를 좋게 보이려고 과업 문구를 유도적으로 쓰지 마세요.**
  ("근처 경기 버튼을 눌러보세요"가 아니라 "근처에서 하는 경기를 찾아보세요")
